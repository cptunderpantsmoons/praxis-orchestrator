# PRAXIS v0.2.0 — Review, Email Bug Fix, Feature Extensions, and TUI

**Date:** 2026-06-22
**Status:** Design — pending user approval
**Scope:** Single bundled effort (bug fix + features + TUI)
**Baseline:** v0.1.0 (live on 2.25.195.193)

## Context

PRAXIS v2.0 is a LangGraph-based async email agent built on FastAPI, deployed at v0.1.0. A code review surfaced a critical email-reply bug, several latent defects, and the absence of any operations interface. This spec bundles the fixes, two feature extensions, and a terminal UI into a single v0.2.0 release.

## Problem Statement

### The email reply bug (critical)

**Symptom (user report):** "Praxis thinks the reply and then takes 2 other replies before delivering the correct prompt."

**Root cause** (in `src/praxis/graph/nodes.py`):

1. `react_node` (lines 601-636): when the model emits free-form reasoning instead of `TOOL:`/`FINAL:` lines, `action_taken` stays `False` and the raw reasoning is assigned to `final_response` (line 636: `final_response = content.strip()`).
2. `_clean_reply_response` (lines 91-93): if every line matches a reasoning pattern, the function falls back to returning the original raw text.
3. Auto-reply fallback (lines 649-729): if `_reply_email` partially succeeds (email sent) but returns a non-"successfully" string, `_send_email` is invoked as a fallback — sending a duplicate email with the same (reasoning) content.

The compound effect: on the first email the model reasons → reasoning is sent as the reply. On the second attempt the model may produce another partial output → second bad reply. By the third attempt the model finally emits a proper `FINAL:` line → correct reply lands. This matches the user's "2 wrong replies, then correct" observation.

### Other findings from the review

- `src/praxis/webhooks/email.py:306` accesses `settings.agentmail_inbox_id`, which is not defined in `Settings` (`src/praxis/config.py`) — latent `AttributeError` at runtime.
- `/admin/*` endpoints have no authentication — anyone with network access can replay failed webhook events.
- `src/praxis/services/agentmail_client.py` is legacy and superseded by `agentmail_v2.py` but still present.
- `src/praxis/services/hindsight_client.py` uses sync `urllib.request` in an async-first codebase.
- `src/praxis/services/{ldr_service,document_service}.py` use `stdlib logging` instead of `structlog`.
- `src/praxis/graph/nodes.py:1045` creates `asyncio.new_event_loop()` inside an async context (anti-pattern).
- `src/praxis/graph/checkpointer.py` silently falls back to `MemorySaver` if Postgres is unavailable — production could lose checkpointing without warning.
- `src/praxis/services/embedding_service.py` hash-embedding fallback produces meaningless vectors — semantic search silently degrades.
- `src/praxis/router/__init__.py` has no circuit breaker — Umans API outage queues all requests indefinitely.
- No frontend/UI exists — the project is backend-only. Operations work (viewing logs, retrying failed events, editing config) requires shell access.

## Goals

1. Eliminate the email reply bug — raw reasoning must never be sent as an email.
2. Eliminate the duplicate-reply failure mode — a single graph invocation must never send the same message twice.
3. Fix the latent `agentmail_inbox_id` AttributeError.
4. Add authentication to `/admin/*` endpoints.
5. Add per-sender reply style — Praxis adapts tone/signature/language based on sender history.
6. Add metrics and observability — model/tool call counts, latency histograms, router concurrency.
7. Build a Textual TUI for ops: dashboard, settings editor, logs viewer, admin actions.
8. All changes behind feature flags where reasonable — v0.1.0 deploy must remain rollback-able.

## Non-Goals (out of scope)

- Draft approval queue, scheduled replies (deferred).
- Removing legacy `agentmail_client.py` (mark deprecated, keep).
- Moving the repo off the mounted drive.
- Replacing `stdlib logging` in `ldr_service.py` / `document_service.py` (low-severity, not blocking).
- Authentication for `/webhook/email` (Svix already handles this).
- Refactoring the `correction_node` event-loop anti-pattern (noted, not blocking).

### Data flow — TUI ops case

```
praxis tui  →  PraxisTUI app boots
            →  reads PRAXIS_ADMIN_TOKEN, PRAXIS_API_URL from .env (or CLI flags)
            →  hits GET /admin/system (localhost:8000 by default)
            →  renders dashboard: router concurrency, checkpointer, service health
            →  user navigates to Settings tab
            →  GET /admin/settings returns current config (secrets masked)
            →  user edits, POST /admin/settings persists to .env, calls reset_settings()
            →  Logs tab: streams from GET /admin/logs/tail (SSE)
            →  Admin tab: list failed events → click Retry → POST /admin/retry-failed
```

### Data flow — email reply (post-fix)

```
Webhook → graph.ainvoke → react_node
  → model = UmansChatModel(...).bind_tools([reply_email, send_email, ...])
  → model.agenerate(messages, tools=...)
  → if response.tool_calls: execute each via _execute_tool, append ToolMessage, continue loop
  → if response.content (no tool_calls): that is the final reply (no reasoning leak possible)
  → if max_iterations=3 hit without resolution: safe fallback reply sent
  → reply_email tool: dedup guard checks AgentState.sent_message_ids; skip if already sent
  → never send raw reasoning, never send duplicates
```

## Component Design

### 1. Email bug fix — `graph/nodes.py` + `chat/wrappers.py`

**`UmansChatModel.bind_tools(tools)`**: passes the tool schemas through to the Umans API (OpenAI-compatible `/v1/chat/completions` with `tools` field). Umans supports the OpenAI tool-calling format for qwen/glm/kimi model families.

**`react_node` rewrite**:
- Build the model with `bind_tools([reply_email_tool, send_email_tool, search_inbox_tool, list_threads_tool, hermes_recall_tool, hermes_store_tool, hermes_learn_tool, deep_research_tool, analyze_document_tool, create_report_tool, delegate_to_agent_tool, list_agents_tool, update_sender_style_tool])`.
- Loop (`max_iterations=3`):
  - `response = await model.ainvoke(messages)`
  - If `response.tool_calls`: for each, execute via existing `_execute_tool`, append `ToolMessage` observations to `messages`, continue.
  - Else: `response.content` is the final reply. Break.
  - If loop exhausts without resolution: send safe fallback reply ("I'm reviewing your email and will respond properly shortly.").
- **Dedup guard**: `AgentState` gains `sent_message_ids: set[str]` in metadata. `_reply_email` and `_send_email` check and add to this set. Duplicate attempts are logged and skipped, counter `replies_sent_duplicate_blocked` incremented.

**`_clean_reply_response`**: stays in the file, only called when `settings.tool_protocol == "legacy"`.

**System prompt update** (`_build_praxis_v22_prompt`): remove `TOOL:`/`FINAL:` format instructions, keep Central Orchestrator identity, security protocols, region-awareness, agency roster. Add "Use the provided tools to send replies and perform actions."

**Feature flag**: `settings.tool_protocol: Literal["native", "legacy"] = "native"`. Default in `.env.example` is `native`. Production can flip to `legacy` to roll back if needed.

### 2. Per-sender reply style — `features/sender_style.py`

```python
@dataclass
class SenderStyle:
    tone: Literal["formal", "casual", "professional"] = "professional"
    signature: str = "— PRAXIS"
    language: str | None = None  # ISO 639-1 code, None = detect from email
    greeting: str | None = None  # optional override
    updated_at: datetime = field(default_factory=datetime.utcnow)
```

- Stored in Neo4j: `(sender:Sender {email})-[:HAS_STYLE]->(:Style {tone, signature, language, greeting, updated_at})`.
- Loaded in `context_loading_node` via `Neo4jContextClient.fetch_sender_style(sender_email)` (new method).
- Injected into the system prompt as a "Reply style for this sender:" block in `react_node`.
- New tool `update_sender_style(tone, signature, language, greeting)` exposed to the ReAct agent — Praxis can learn style from a user's correction ("be more casual with me").
- Defaults: when no style entry exists, use `settings.default_tone` and `settings.default_signature`.
- Flag: `settings.sender_style_enabled: bool = True`. When `False`, the style loading and tool are skipped entirely.

### 3. Metrics + observability — `features/metrics.py`

```python
class MetricsRegistry:
    """Thread-safe async metrics singleton."""
    counters: dict[str, int]          # e.g. "model_calls:umans-flash"
    histograms: dict[str, list[int]] # e.g. "model_latency_ms:umans-flash" (bucketed)
    gauges: dict[str, int]            # e.g. "router_active:umans-flash"
```

Instrumentation points:
- `UmansConcurrencyRouter.acquire/release`: update `router_active:{model}` and `router_peak:{model}` gauges, `router_global_active`, `router_global_peak`.
- `UmansChatModel._agenerate`: increment `model_calls:{model}`, record `model_latency_ms:{model}`.
- `_execute_tool`: increment `tool_calls:{tool}`, `tool_success:{tool}` or `tool_failure:{tool}`, record `tool_latency_ms:{tool}`.
- `receive_email` webhook: increment `emails_received`.
- `reply_email` / `send_email` tools: increment `emails_sent`, `emails_failed` on failure, `replies_sent_duplicate_blocked` on dedup skip.

Export:
- `GET /admin/metrics` — JSON dump.
- `GET /admin/metrics/prom` — Prometheus text format (counter/histogram/gauge conventions).
- `POST /admin/metrics/reset` — zero all counters/gauges (admin-only).

### 4. Admin endpoints — `webhooks/admin.py` + `webhooks/auth.py`

**`webhooks/auth.py`** (new):
```python
async def require_admin_token(authorization: str = Header(None)) -> None:
    expected = settings.praxis_admin_token
    if not expected:
        raise HTTPException(500, "PRAXIS_ADMIN_TOKEN not configured")
    if not authorization or not authorization.startswith("Bearer "):
        raise HTTPException(401, "Unauthorized")
    if not secrets.compare_digest(authorization[7:], expected):
        raise HTTPException(403, "Unauthorized")
```

All `/admin/*` endpoints depend on `Depends(require_admin_token)`.

New endpoints (all auth-gated):

| Method | Path | Purpose |

| GET | `/admin/logs/tail` | SSE stream of structlog output |

| GET | `/admin/metrics` | JSON metrics dump |

## Error Handling

- All new admin endpoints: 401 (no token), 403 (bad token), 422 (bad payload), 500 (with structlog error logged).
- TUI network errors: show error toast, keep last-known-good state in widgets, retry with exponential backoff (1s, 2s, 4s, max 10s).
- Settings write failures (`.env` not writable): return 500 with message, don't call `reset_settings()` (keep old config live).
- Native tool-calling: if the Umans API returns a tool_call with an unknown name, log warning and return a `ToolMessage` with error text — let the model recover.
- Dedup guard: log `replies_sent_duplicate_blocked` counter and the message_id; never raise.
- Per-sender style: if Neo4j is down, fall back to global defaults with a logged warning (matches existing graceful-degradation pattern).
- Safe fallback reply: if sending the fallback also fails, log `emails_failed` and persist the event to the dead-letter queue.

## Security Considerations

- `PRAXIS_ADMIN_TOKEN` must be at least 32 characters. `.env.example` includes a placeholder with a comment.
- `/admin/*` endpoints: 401 when no token is provided, 403 when a token is present but invalid. These are distinct cases (missing vs. wrong) and using the correct status code aids client-side debugging and audit log clarity. Both responses use the generic detail string `"Unauthorized"` to avoid leaking token validity state.
- Settings write endpoint validates field names against an allowlist — no arbitrary env var writes.
- Secret masking in `GET /admin/settings`: returns `"***"` for non-empty secret fields, `""` for empty. `POST /admin/settings` treats `"***"` as "no change" (preserves the existing value).
- TUI connection: bearer token stored in `.env` (not committed) or passed via CLI flag (not persisted). Never logged.

## Rollback Plan

If v0.2.0 misbehaves on production:
1. Set `tool_protocol=legacy` in `.env` → reverts to the `TOOL:`/`FINAL:` protocol.
2. Set `sender_style_enabled=false` → disables per-sender style injection.
3. Restart the app — TUI and new admin endpoints remain available but the core email flow uses the v0.1.0 behavior.

If the TUI or admin endpoints cause issues:
1. Remove the `praxis tui` CLI command from the deployment.
2. Restrict network access to `/admin/*` at the reverse proxy (Traefik) layer.
