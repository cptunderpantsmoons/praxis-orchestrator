# PRAXIS v2.0 — One-shot remote bootstrap

This file is a complete, self-contained deploy of PRAXIS v2.0 for a fresh
Ubuntu 22.04/24.04 server. It is designed to be run **once, by a human**,
from the server's console (KVM, VNC, or web shell) — no SSH required.

## What it does (in order)

1. Installs Docker + docker-compose plugin
2. Installs git
3. Creates the `/opt/praxis` directory tree
4. Prompts you to paste the 4 production secrets
5. Writes a real `.env` to `/opt/praxis/repo/.env` (chmod 600)
6. Clones the GitHub repo into `/opt/praxis/repo`
7. Builds the Docker image
8. Starts Neo4j, Qdrant, PostgreSQL
9. Starts the PRAXIS app
10. Waits for `/health` to return 200
11. Runs the smoke test

## How to run it

You need ONE of these:

- A working SSH login (with `root` or any sudo user)
- The Hostinger KVM console
- The Hostinger web shell

Then:

```bash
# 1. Log in to the server
# 2. Paste this whole file as /tmp/praxis-bootstrap.sh (or curl it)
# 3. Run it:
chmod +x /tmp/praxis-bootstrap.sh
bash /tmp/praxis-bootstrap.sh
```

You will be prompted for:
- `AGENTMAIL_API_KEY`   (the am_us_... key)
- `AGENTMAIL_WEBHOOK_SECRET`   (the whsec_... key)
- `UMANS_API_KEY`       (the sk-R-... key)
- `GITHUB_TOKEN`        (the ghp_... key)
- (optional) `HOSTINGER_API_KEY`, `COMPOSIO_API_KEY` if you want to wire those in later

The script does not echo the keys back. It just writes them to the `.env` file
with `chmod 600` and continues.

## Why this script exists

We discovered that the password provided for the deploy target is not accepted
by the server's sshd. Rather than spin on the auth problem, this script
side-steps SSH entirely — the operator pastes it via the host's web console
or KVM, and the script does the rest.

## What it does NOT do

- It does NOT send metrics to a remote aggregator
- It does NOT open ports in the firewall (you must do that in the Hostinger
  panel: open inbound 80, 443, 8000)
- It does NOT register a domain or set up DNS (use Hostinger's DNS panel)
- It does NOT back up data (set up cron + S3 separately)

## After deploy

```bash
# Watch logs
cd /opt/praxis/repo && docker compose logs -f app

# Restart after config change
cd /opt/praxis/repo && docker compose restart app

# Update to a new version
cd /opt/praxis/repo && git pull && docker compose build app && docker compose up -d app

# Verify it's still up
curl http://localhost:8000/health
```

## Files written to the server

- `/opt/praxis/repo/.env`                — secrets, chmod 600
- `/opt/praxis/repo/`                     — full repo (cloned from GitHub)
- Docker volumes for neo4j, qdrant, postgres (in `/var/lib/docker/volumes/`)

## Rollback

To roll back, run:
```bash
cd /opt/praxis/repo
git checkout v0.1.0
docker compose down
docker compose build app
docker compose up -d
```

To wipe all data:
```bash
cd /opt/praxis/repo && docker compose down -v
```
